# VoiceEmo Studio for iOS

**Product requirements · 13 November 2026 · Draft for implementation**

Build a native Swift app that turns a story into a full-cast audiobook. A reader can bring a link, a file, or pasted text, hear a free opening without signing in, and continue listening while the rest of the book is generated. Returning readers can find their private books and resume playback.

**First build** · iPhone, SwiftUI, iOS 17.4+, existing VoiceEmo FastAPI backend. The minimum OS and the release sequence below are proposed VoiceEmo decisions. The first deliverable is a guest import-to-playback flow on a real iPhone. A paid App Store release additionally requires durable generation, account recovery and deletion, and production StoreKit verification.

## 2. Audience and release scope

The primary user reads web fiction, fanfiction, or a draft they can submit and wants to listen on a phone. Their first success is hearing distinct speakers from their own story. Their return visit starts with the last book and listening position.

| Release | User-visible scope | Exit condition |
| --- | --- | --- |
| **M1 · Guest vertical slice** | Create from link, Files, or paste. Show import state. Play a free preview, select a transcript line, switch between the full and mini player, and reopen from a device library. Include at least one original audition sample. | Real iPhone can import all three sources against staging, play server MP3s and test-device speech fallback, respect the preview limit, resume after relaunch, and continue on lock screen. |
| **M2 · TestFlight** | Production-like speech pipeline, progressive full-book rendering, reliable account claim and library sync, persistent progress, private book and account deletion, VoiceOver, Dynamic Type, and a 16-item original showcase. Add a limited beta entitlement through the backend. | Long books survive server and client restarts. Two devices resume correctly. Device audio and approved live source fixtures pass. |
| **M3 · App Store v1** | StoreKit one-book credit, verified redemption, synchronized entitlements, purchase recovery, player speed and chapter navigation where available, account management. | Apple Sandbox purchase, restore/reconcile, refund, privacy review, and release gates pass. |
| **Follow-up** | Recurring plans, richer speaker editing and voice auditions, download for offline playback, a share extension, ready-to-listen notifications, and ZIP export through the iOS share sheet. | Choose after preview conversion, playback quality, generation cost, and App Review feedback are measured. |

The backend already has free unlock and web subscriptions. An explicit server environment policy enables free full unlock in internal builds. Paid environments enforce billing for guest continuation, including when StoreKit or Stripe configuration is incomplete.

**Player state** · `idle → buffering → playing / paused → previewEnded or finished`. An interruption can pause without resetting the queue. Generation has its own state machine. The client can represent `playing + generating`, `paused + generationFailed`, and `previewEnded + ready` without overloading a single UI state.

## 4. Swift implementation

- **App and views** · One SwiftUI app target with Create, Library, Player, and Account features. Use `NavigationStack`, an observable playback coordinator shared across tabs, a full player sheet, and a persistent mini player. Keep the view models on the main actor. Keep transport, file staging, media caching, and background work off the UI thread.
- **Imports** · Use SwiftUI `fileImporter` and `UniformTypeIdentifiers`. Resolve and release security-scoped URLs, copy to protected app storage, and use a file-backed multipart upload. Report byte progress from `URLSession`. For background uploads, use a background session and reconcile its task with a saved import ID. Delete temporary copies at terminal completion or cancellation. Keep large document parsing on the server. [Apple Files importer](https://developer.apple.com/documentation/swiftui/view/fileimporter(ispresented:allowedcontenttypes:oncompletion:)), [Apple background transfer](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background).
- **Media** · Start with authenticated MP3 downloads through the existing `URLSession` and enqueue local clips in `AVQueuePlayer`. Keep a bounded look-ahead, cancel pending fetches on a book/voice change, and key clips by book, line, and cast revision. Publish Now Playing metadata and remote commands through MediaPlayer. Use an active playback audio session with `.spokenAudio` and the audio background capability. Use `AVSpeechSynthesizer` for the current browser-mode equivalent in internal builds. That mode depends on installed voices and is a separate production quality decision. [Apple media playback setup](https://developer.apple.com/documentation/avfoundation/configuring-your-app-for-media-playback), [Apple remote controls](https://developer.apple.com/documentation/mediaplayer/handling-external-player-events-notifications).
- **Storage** · Use local storage for draft metadata, in-flight import IDs, an account-scoped library snapshot, and the last resume checkpoint. Protect staged files and temporary audio using iOS file protection. Keep media cache eviction separate from ownership. Upload positions on pauses, seeks, a throttled interval, and lifecycle transitions. Resolve concurrent positions using a server revision and retry local unsynced intent after fetching the new revision.
- **Identity** · For M1, use a persistent `URLSession` with the existing guest session and bootstrap it once before concurrent private requests. For beta, use Sign in with Apple. Provide a verified web account linking flow before offering cross-platform purchase access. Add native sign-in endpoints that associate the verified identity and claim the guest library transactionally. If Google/Discord or an email continuation uses the browser, use `ASWebAuthenticationSession` with an associated HTTPS callback and a short-lived, one-time exchange bound to native-held PKCE/state. Link accounts only after both sides prove ownership. Store native refresh credentials in Keychain. [Apple authentication services](https://developer.apple.com/documentation/authenticationservices), [Apple App Review login and privacy](https://developer.apple.com/app-store/review/guidelines/).

## 5. Backend contract and generation

Keep FastAPI for sourcing and extracting stories, attribution, rendering, account and library storage, and verified entitlements. Keep model and provider secrets on the server. M1 reuses the existing routes shown here. The versioned mobile additions are proposed routes.

| Capability | Current route and behavior | Work for iOS |
| --- | --- | --- |
| Guest and library | `GET /api/account` issues a guest cookie. `GET /api/my/books` lists owned imports. `DELETE /api/my/books/{id}` removes one. | Bootstrap cookie once. Add native token session/refresh and account deletion. Add stable job state and progress to library items. Guard against guest claim racing with upload completion. |
| Import | `POST /api/import` accepts multipart `url`, `text`, or `file`. It returns a cast book synchronously after extraction. | Keep for M1. Add `POST /api/v1/imports` returning `202` with import ID and `GET /api/v1/imports/{id}` for parse/cast/preview status and recoverable failures. Accept an idempotency key and define cancel behavior. |
| Book and transcript | `GET /api/books/{id}` returns roster, chapters, initial lines, `preview_lines`, `total_lines`, and `provider`. `GET /api/books/{id}/lines?start=&count=` pages indexed lines. Preview and ownership are server-gated. | `preview_lines` is the playable limit in the current contract, including the full range after unlock. Add stable line/speaker IDs and revisions. Return only entitled transcript and media. |
| Playback | `GET /api/books/{id}/lines/{index}/audio` returns MP3 (`200`) or device speech cue (`204`). It requests individual renders on demand and blocks beyond the available access range. | Add `GET /api/v1/books/{id}/manifest` with versioned segments, line ranges, actual timing metadata, availability, and authorized locations. Add a priority queue for full-book generation and prefetch. Release can start with independently playable ordered chunks. Benchmark before choosing HLS. |
| Cast revision | `GET /api/voices`, `POST /api/books/{id}/cast`, and `GET/POST /api/books/{id}/ai-cast`. | Expose a stable roster in beta. Defer manual recast UI if needed. Accept updates per owner, rotate revision, and invalidate affected cached clips. Shared catalog books need owner-scoped overrides before they expose voice edits. |
| Resume | Existing web playback position lives in local storage. | Add `GET/PUT /api/v1/books/{id}/progress` with `lineID`, `offsetMs`, `revision`, and server time. Use local state for guest or offline updates. |
| Access | Web uses `POST /api/my/books/{id}/unlock`, checkout, and Stripe credit routes. | Add StoreKit transaction verification and an atomic book-credit redemption operation. Read the same authoritative book access state from either client. Enforce the production paywall independently of provider availability. |
| Export/discovery | `GET/POST /api/books/{id}/export`, `GET .../export/download`, and `/api/library/{featured,search,open}`. Samples currently live in web JS. | Preserve export for later native UI. Use a shared owned sample manifest or bundle in Swift. Treat the external public-domain catalog as optional and give it a graceful empty/error state. |

Persist `Import`, `Book`, `Chapter`, `Speaker`, `TranscriptLine`, `Segment`, `Job`, `Progress`, `PurchaseTransaction`, and `Entitlement` in durable storage. Render work is unique per book, script/cast revision, and segment index. Stage each segment until it is valid and publish it atomically. Prioritize the opening and the listener’s current playable window. Retry transient provider errors with backoff. After restart, resume unfinished work from the last published segment. When a later segment fails, keep the ready prefix playable. Persist jobs and serve private media before launching a paid build. The starter's on-demand line rendering and in-memory export job maps are a starting point for M1.

The manifest tracks the entitled end and the last rendered segment separately. Bounded polling while waiting for new audio is sufficient initially. Return structured errors for locked content, segments still rendering, provider failure, expired sessions, and deleted books. Rate-limit free previews and cap the amount rendered before entitlement. Test that an interrupted or retried render cannot double-spend a credit.

## 6. Native purchase policy

Use StoreKit 2 for digital book unlocks in the App Store build, keeping Stripe checkout on the web. StoreKit displays the storefront price. Start with a single consumable credit for one full-book generation. Credit purchases do not expire. Verify signed transactions on the server, bind to a stable account UUID with `appAccountToken`, deduplicate by Apple transaction ID, credit the account before finishing the transaction, and make redeeming a credit atomic with unlocking the chosen book. Reconcile unconsumed credits and permanent book access from the user's signed-in server ledger. StoreKit restores restorable products where relevant. Finished consumables reconcile through the server ledger. Handle StoreKit transaction updates and App Store Server Notifications V2 for refunds and reversals. [Apple In-App Purchase rules](https://developer.apple.com/app-store/review/guidelines/#payments), [StoreKit testing](https://developer.apple.com/documentation/storekit/testing-at-all-stages-of-development-with-xcode-and-the-sandbox), [App Store Server Notifications](https://developer.apple.com/documentation/appstoreservernotifications).

The ability to create audio from user input makes reader-app eligibility uncertain. Record current storefront rules and cross-platform entitlement behavior in the App Review submission. Evaluate a recurring plan after usage and costs are measured. Treat its included periodic allowance as a separate product decision requiring review. The current Stripe expiring-credit logic should be kept separate from non-expiring StoreKit credit purchases.

## 7. QA, metrics, and release gates

| Gate | Evidence to collect |
| --- | --- |
| Import quality | Approved public sample for each advertised host, 100 MB boundary fixture, UTF-8 TXT, valid EPUB reading order, DOCX, selectable PDF, image-only PDF, malformed or restricted input, interrupted upload, and duplicate retry. Record unsupported hosts as unavailable and provide Files or Paste. |
| Casting | Review a corpus of annotated scenes for speaker attribution, first-person narrator, dialogue turns, two speakers in one paragraph, and stable voices over multiple chapters. Proposed beta target is at least 90% correct speaker assignments on labeled dialogue lines, with a per-source breakdown. |
| Playback and recovery | Small and large iPhone, oldest supported OS and current OS, physical devices. Cover rapid seeking, lock screen, headphones/Bluetooth, interruption, slow network, reconnect, chapter jumps, rates, full-book continuity and independent simultaneous sessions. |
| Ownership and payments | Guest migration plus second account isolation. Reinstall/relogin, cross-device sync, deletion mid-generation, pending or cancelled purchase, double delivery, duplicate credit redemption, refund, and access reconciliation. Use Xcode StoreKit tests for UI and Apple Sandbox for server verification. |
| App Store readiness | Original VoiceEmo presentation, privacy disclosures and labels, stated AI subprocessors, in-app account deletion, review steps, and staged samples using owned or licensed content. [Apple App Review guidelines](https://developer.apple.com/app-store/review/guidelines/). |

Measure import acceptance rate by source, time from accepted import to first audible preview, preview starts, preview completion, continued listening, stalls per listening hour, and render cost per generated audio hour. Suggested initial release goals on representative staging fixtures are p95 time to playable preview under 45 seconds **after upload completes**, warm seek under 1 second, and at least 95% successful accepted imports across the curated launch corpus. Report cold seeks and unqualified hosts separately. Collect event IDs, coarse source type, durations, and outcomes. Story URLs, text, documents, transcripts, and account email stay out of telemetry.

## 8. Build order and decisions

1. **Contract and fixtures** · Freeze existing API examples and mock server responses. Collect a test corpus with consent, a demo book, and one real MP3 fixture. Confirm which hosts work from the intended deployment.
2. **First device slice** · Build the SwiftUI Create → Preview → Library path with the guest API. Verify all input types, audio fallback and server MP3, transcript seek, and lock screen on device.
3. **Service changes** · Deliver durable import and segment jobs, playback manifests, native sign-in, resume sync, ownership and deletion. Run long-book failure and restart tests.
4. **Commerce and release** · Measure quality and cost in TestFlight, integrate StoreKit and entitlement reconciliation, qualify the paid build on Apple Sandbox, and submit for App Review.

Before implementation sign-off, decide the opening length, initial language and source coverage, cost cap per preview and per book, launch price and credit policy, and whether offline is required for v1. Also decide the maximum renderable length and unit-count rule before a user spends a credit. The current starter uses 12 preview lines as the M1 default. Use a server policy so production preview eligibility and duration can be tuned without a client release.

# Book and audiobook sources for The Teller

Verified November 14, 2026. Scope is a private, single-user app that can create a performed audiobook from a readable text or play an existing full recording.

## Recommended integration

Use **Project Gutenberg** for text that The Teller casts and narrates. Use **LibriVox** for ready-to-play human recordings, with chapter media served by the Internet Archive. Keep these choices labeled separately in discovery and playback. A Gutenberg edition can produce a speaker-labeled transcript and selectable voices. A LibriVox project already has a performance, narrator credits and chapter timings. It may use a different translation, source edition, or chapter split. [Project Gutenberg offline catalog](https://www.gutenberg.org/ebooks/offline_catalogs.html) · [LibriVox API](https://librivox.org/api/info)

## Rights and identifiers

Track the underlying text edition, translation, cover and audio recording separately. Each can have a different rights holder and territorial status. A work’s availability to read, borrow or buy is an access signal. Reuse for narration, storage or distribution depends on the particular asset’s rights and the access provider’s terms. For a sourced edition retain provider ID, language, canonical source link, rights basis, territory, date checked, and an edition version or checksum where available. For a recording retain provider project and track IDs, reader credits, source edition link and recording rights. [U.S. Copyright Office on recordings and underlying works](https://www.copyright.gov/register/sr-choose.html) · [Project Gutenberg permissions](https://www.gutenberg.org/policy/permission.html) · [Wikisource reuse policy](https://en.wikisource.org/wiki/Wikisource:Reusing_Wikisource_content)

Use namespaced provider IDs. A Gutenberg ebook number identifies a digital edition. A LibriVox project number identifies a recording, which can point to a separately identified Archive item. Open Library distinguishes a work identifier from its edition identifier, and Google Books uses volume IDs. Deduplicate within a source by ID. When grouping across sources, use exact identifiers or a reviewed mapping, with title and author as candidate evidence. Preserve distinct editions and translations. [Gutenberg catalog metadata](https://www.gutenberg.org/ebooks/offline_catalogs.html) · [LibriVox project fields](https://librivox.org/api/info) · [Open Library search schema](https://openlibrary.org/dev/docs/api/search) · [Google Books volumes](https://developers.google.com/books/docs/v1/reference/volumes)

## Project Gutenberg and Gutendex

**Catalog and quota.** Project Gutenberg directs automation to machine-readable files, designated harvesting, and mirrors. Its weekly CSV is the simplest local index. Daily RDF provides richer records and format metadata. The official feed directory on the observation date listed about 5.3 MB for the compressed CSV, 121 MB for the compact RDF archive, and 11 GB for the weekly full-text archive. The project plans to retire the XML OPDS feeds in 2027 and is testing JSON OPDS 2. Its robot policy examples include a two-second wait for the dedicated harvest endpoint. For a full private mirror, its guide recommends rsync with periodic refreshes. These are keyless public sources. [Offline catalogs](https://www.gutenberg.org/ebooks/offline_catalogs.html) · [Feed directory](https://www.gutenberg.org/cache/epub/feeds/) · [Robot access](https://www.gutenberg.org/policy/robot_access.html) · [Mirroring guide](https://www.gutenberg.org/help/mirroring.html)

**Full text and rights.** The app uses the exact ID from the catalog and verifies the edition identity and U.S. public-domain statement in the mirror’s `pg<ID>.rdf` before fetching `pg<ID>.txt`. The loader checks the book’s start and end markers, preserves the complete body and joins hard-wrapped lines within paragraphs. The CSV’s `Type=Text` excludes audio-only records. The CSV has no rights column, so an expanded-catalog search hit can have unknown status until checked on open. Treat restrictions as asset-specific and check rights for the intended territory if distributing outside the U.S. Project Gutenberg’s permission guidance separates reuse of public-domain material from use of its name and branded copies. [Catalog and mirrors](https://www.gutenberg.org/ebooks/offline_catalogs.html) · [Permissions](https://www.gutenberg.org/policy/permission.html) · [License](https://www.gutenberg.org/policy/license.html)

**Gutendex.** The public demo is a keyless JSON layer over Gutenberg metadata. For example, `GET /books?search=austen&languages=en&copyright=false&mime_type=text%2Fplain` returns up to 32 results per page, with continuation URLs and MIME-to-file URL mappings. `GET /books/{id}` resolves a single Gutenberg edition. `copyright=false` represents U.S. public domain and a null status means unavailable rights data. The listed download links refer to file hosts. The publisher asks long-term users to run their own instance and documents no guaranteed public-demo request budget. With the local index already in place, Gutendex is optional. [Gutendex API](https://gutendex.com/) · [Gutendex source and self-hosting](https://github.com/garethbjohnson/gutendex)

**The Teller.** The 12-title seed works without a catalog download. Set `GUTENBERG_CATALOG_PATH` to a locally downloaded `pg_catalog.csv` or `pg_catalog.csv.gz` to expand search. Refresh the snapshot out of band. The default generated-file bases are the PGLAF and Old Dominion University HTTPS mirrors. `GUTENBERG_MIRROR_URL` configures a private or approved HTTPS mirror; it should point at the generated collection containing per-ID directories. The server gives each reader a private reusable copy and rejects editions above its configured length limit, preserving the complete text of accepted books. [Catalog loader](book_catalog.py) · [Seed](catalog_seed.json) · [Server](server.py) · [Official mirror list](https://www.gutenberg.org/MIRRORS.ALL)

## LibriVox and the Internet Archive

**Catalog and quota.** LibriVox’s keyless `GET /api/feed/audiobooks/` supports title, author and genre search, `id`, `offset`, and `since` for incremental updates. Ask for `format=json` and `extended=1` on open to get sections and the Archive project URL. It also exposes a track feed and per-project RSS enclosures. The documented default is 50 records and the September 2026 maximum is 500 per request. LibriVox asks clients to space requests by several seconds and describes possible future per-client 429s. One filtered query or a cached manifest is cheaper than synchronizing the entire catalog. [LibriVox endpoints](https://librivox.org/api/info) · [September 2026 API update](https://librivox.org/2026/09/16/librivox-api-update/)

**Media and rights.** Internet Archive’s public item metadata response at `GET /metadata/{identifier}` lists files and item metadata. Use a LibriVox project’s ordered, vetted chapter URLs or RSS enclosures for playback rather than guessing the chapter list from the archive directory. That directory can include duplicate encodings, alternate bitrates, covers and other files. Canonical downloads can redirect to storage nodes. LibriVox describes released recordings as public domain and welcomes sharing. Use the confirmed collection and item-level rights, keep reader attribution, and check cover rights independently. Treat Archive files outside a confirmed project as their own source with their own permissions. [LibriVox rights policy](https://librivox.org/pages/public-domain/) · [LibriVox API update](https://librivox.org/2026/09/16/librivox-api-update/) · [Archive metadata API](https://archive.org/developers/md-read.html) · [LibriVox Archive collection](https://archive.org/details/librivoxaudio)

**The Teller.** `GET /api/catalog/human` provides search and paging, and `GET /api/catalog/human/{id}` provides an ordered chapter manifest. The backend uses the official feed, a three-second minimum request interval, bounded responses, an RSS fallback, and cached results for transient failures. It exposes validated HTTPS Archive media URLs. Chapter media delivery runs separately from API metadata calls. The native player uses an elapsed-time control and a local chapter/offset checkpoint for recordings, with generated transcripts handled by the studio player. [Adapter](human_audio.py) · [Native recordings player](ios/TheTeller/UI/TellerHumanAudioView.swift)

## Additional public-text and recorded-audio sources

### Standard Ebooks

Standard Ebooks provides individual DRM-free EPUBs with consistently structured markup and clean chapter boundaries. It uses public source repositories with version histories. Its own work is dedicated to the public domain, and it describes the underlying texts and source cover art as believed to be in the U.S. public domain. For a curated shelf, use the explicitly selected edition’s EPUB or pin its public source revision and record provenance. The New Releases Atom/RSS feeds are open. Full-catalog OPDS and bulk downloads are generally a Patrons Circle benefit. The official feeds also offer eligibility routes for producers, sponsors and some open-source projects. OPDS 2 uses the `application/opds+json` Accept header. No public JSON-search quota is specified in the cited materials. [About and rights](https://standardebooks.org/about/standard-ebooks-and-the-public-domain) · [DRM and accessibility](https://standardebooks.org/about/accessibility) · [Feeds](https://standardebooks.org/feeds) · [Bulk downloads](https://standardebooks.org/bulk-downloads) · [Source repositories](https://github.com/standardebooks)

### Open Library

The public search API at `GET /search.json` supports author, title, ISBN and work or edition fields. The Read API maps identifiers to readable or borrowable copies. `ebook_access:public` can narrow discovery to publicly readable editions, while the linked item still needs an independent suitability and rights check before full-text ingestion. Open Library asks for caching and batch searches at low volume, sets 1 request per second for unidentified calls and 3 per second for an identifying User-Agent with contact, and supplies monthly dumps for bulk. The catalog’s public-domain and CC0 contribution policies cover metadata. A returned cover, downloadable text or loan carries its own rights. For The Teller, use this provider only if ISBN or metadata enrichment becomes valuable enough to add a dependency. [Search API](https://openlibrary.org/dev/docs/api/search) · [Read API](https://openlibrary.org/dev/docs/api/read) · [Limits and dumps](https://openlibrary.org/developers/api) · [Catalog data policy](https://openlibrary.org/help/faq/using)

### Google Books

`GET /books/v1/volumes` searches by title, author, ISBN and other terms and supports up to 40 volumes per page. Google documents API identification for public calls and OAuth 2.0 for private user data. The API key identifies the project for access and quota. No universal requests-per-day value is specified in the cited Books docs. Availability and download links vary by location, edition and account. `accessInfo.publicDomain`, `viewability` and EPUB/PDF links provide separate signals. A link may point to a sample or depend on purchased access. The additional Books terms require a separate agreement or written permission to charge users for the application. The general API terms place conditions on permanent copies, caching and derivative uses. The Teller’s direct Gutenberg lookup avoids this dependency and the risk of a search record resolving to a different edition. [API credentials and access](https://developers.google.com/books/docs/v1/using) · [Volume search reference](https://developers.google.com/books/docs/v1/reference/volumes/list) · [Books API terms](https://developers.google.com/books/terms) · [Google APIs terms](https://developers.google.com/terms)

### Wikisource

Use standard MediaWiki public search through `/w/rest.php/v1/search/page`, then identify the correct language, edition and revision. Wikisource’s download feature uses WS Export for EPUB and other formats on supported works. One work can span multiple transcluded or linked pages, so validate export completeness, chapter order and proofreading state before admitting it to the catalog. The site contains both public-domain and freely licensed works. Check the work and translation copyright tags and preserve required attribution and share-alike terms. Wikimedia requires an identifying User-Agent, encourages caching and low concurrency, and asks clients to honor 429 `Retry-After`. Public reads need no OAuth token, with OAuth available for authenticated limits. Use an allowlist for the first few books if exact editions are needed. [REST reference](https://www.mediawiki.org/wiki/API:REST_API/Reference) · [API access policy](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy) · [Rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits) · [Wikisource download help](https://en.wikisource.org/wiki/Help:Reading_offline) · [Reuse policy](https://en.wikisource.org/wiki/Wikisource:Reusing_Wikisource_content)

### Project Gutenberg Open Audiobook Collection

The Project Gutenberg, Microsoft and MIT release consists of almost 5,000 already-generated audiobooks. Its project site and paper describe automated text cleaning and neural narration. Its keyless RSS feed carries MP3 enclosures hosted on the Internet Archive. This fixed collection can be indexed from the feed or verified item list. No interactive API quota is published in the reviewed materials. Project Gutenberg describes the listed audio collections as open and U.S. public domain. Retain project and item provenance, check the rights listing for each recording before republishing, and label it as computer narrated. For The Teller it is an optional recording source when fast availability matters. Resume by the original item and its audio time. [Project Gutenberg audio listings](https://www.gutenberg.org/?openBrowser=true) · [Project website](https://marhamilresearch4.blob.core.windows.net/gutenberg-public/Website/index.html) · [Research paper](https://arxiv.org/abs/2309.03926) · [RSS feed](https://marhamilresearch4.blob.core.windows.net/gutenberg-public/rss.xml) · [Archive collection](https://archive.org/details/gutenberg-audiobooks)

## Borrowing and commercial services

### OverDrive / Libby

OverDrive offers approved integrations for Discovery metadata and collection availability, Title Link for Libby links, and Circulation for patron-specific checkout, holds and downloads. Discovery and Title Link use OAuth client credentials. Circulation uses patron authentication and depends on the institution, patron access and selected format. Vendors may need a separate client key and secret per institution. The API license controls presentation, metadata freshness, territories and access models, with documented limits varying by API and partner setup. The supplied test environment applies after integration access. In a private app, prefer linking to Libby if the user wants to find a loan. Any later native borrowing integration belongs under OverDrive’s approval and lending rules. [Application process](https://developer.overdrive.com/getting-started/application-process) · [Authentication](https://developer.overdrive.com/api-docs/authentication) · [Circulation API](https://developer.overdrive.com/api-docs/circulation-apis) · [API license](https://developer.overdrive.com/terms-and-conditions) · [Test environment](https://developer.overdrive.com/getting-started/integration-library)

### Spotify

The OAuth Web API has audiobook metadata and chapter endpoints, with country and user-account availability rules, and library endpoints requiring user authorization. The chapter’s 30-second preview field is deprecated and may be null. Spotify restricts downloading, standalone previews, integration with other streams, and use of Spotify content in AI models. Development mode has a Spotify Premium requirement and up to five allowlisted authenticated users per app. The July 2026 change made API consumption quota shared across a developer’s development-mode client IDs. Ordinary rate limits use a rolling 30-second window with thresholds that vary by mode. Extended quota has separate eligibility and review. The Teller can send the reader to Spotify via a standard service link. [Audiobook API](https://developer.spotify.com/documentation/web-api/reference/get-an-audiobook) · [Chapter API](https://developer.spotify.com/documentation/web-api/reference/get-a-chapter) · [Saved audiobooks](https://developer.spotify.com/documentation/web-api/reference/get-users-saved-audiobooks) · [Developer policy](https://developer.spotify.com/policy) · [Quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes) · [July quota update](https://developer.spotify.com/blog/2026-07-23-web-api-quota-updates) · [Rate limits](https://developer.spotify.com/documentation/web-api/concepts/rate-limits)

### Audible

The Audible consumer license grants personal, noncommercial access to purchased recordings. Its conditions restrict transfers, copying, distribution, commercial exploitation and bypassing DRM. ACX’s documented workflow gives rights holders a way to grant Audible distribution rights in recordings they submit. No official public endpoint or quota for importing customers’ complete Audible audiobooks was identified in the reviewed materials. Leave playback in Audible unless a separate approved agreement provides integration terms. [Audible consumer license](https://www.audible.com/legal/license-agreement) · [Service conditions](https://www.audible.com/legal/conditions-of-use/) · [ACX distribution agreement](https://help.audible.com/s/article/audiobook-license-and-distribution-agreement-ua)
